# Proposal v2 修改汇总与需求对照

版本日期：2026年10月22日

本次以 v1 中的 Word proposal 和 petteri.md 会议转录为依据，重写英文 proposal。原稿保留在 v1。v2 的重点是让项目目标、系统流程、三条工作线、用户功能、实验、验收和计划互相对应。未确认的技术路线写成待验证问题，不写成已经实现的能力。

## 1 核心定位的修改

原稿主要定位为“完整 SEB 遥测接入＋多模态信号融合＋阈值研究工作台”，并将生产复核界面列为范围外。老师强调的核心却包含独立的证据管理和人工复核应用。因此 v2 将三条工作线重新定义为：

1. WP1 采集与集成：先理解现有考试工具，验证摄像头、麦克风、传输和考试身份关联。
2. WP2 证据管理与复核应用：存储、时间线、回放、管理员、学生、审核员和评审成员功能。
3. WP3 行为分析与评估：比较现成工具，集成有限的检测能力，测量错误与局限。

阈值比较保留为分析评估方法；基础的可配置复核优先级评分纳入最低范围，复杂仪表盘、融合评分优化和转录属于扩展。基本回放和人工复核属于必交付内容。正式处分和生产仲裁服务仍在范围外。

## 2 主要流程的修改

原稿分散描述采集、检测与阈值，没有完整交代用户如何考试、证据如何到达人工审核。v2 第3.7节给出十步流程：管理员建立考试与权限 → 学生知情同意和设备检查 → 建立考试与证据会话关联 → 开始答题和采集 → 音视频传输与保存 → 分析并标记时间段 → 中断记录与恢复 → 考试结束并完成归档 → 审核员回放与记录意见 → 评审成员查看并补充意见。

关键边界贯穿流程：系统标记或采集故障不能自动终止、提交或判定考试；低质量音视频是技术状态，不是作弊结论；人工作出的复核记录与模型观察分别保存。

## 5 验收口径的修改

原稿把高阶模型能力、跨平台、群体公平性评估和完整平台集成写成硬性要求，容易把研究不确定性变成交付承诺。v2 区分：

- 必交付行为：录音录像、会话正确关联、证据回放、角色权限、人工记录、基础人脸计数与语音活动观察、可配置复核优先级评分、错误和局限报告。
- 必开展调查：SEB、SEB Server、Moodle、嵌入方式、WebRTC接收与录制；调查必须可复现，不等于必须证明所有路线成功。
- 有条件扩展：头部姿态、手机或书本检测、多人说话区分、转录、实时提示、融合评分优化和复杂阈值看板。

M1验收未改动工具栈；M2验收一条可用采集路线和集成结论；M3验收证据复核应用与基础分析；M4验收完整流程和评估；M5验收可复现交付。失败实验不能冒充成功集成，但可以成为有价值的研究结果。

## 7 删除或降级的承诺

删除未经支撑的行业采用比例、“市场没有任何成熟工具”、“所有同类系统不提供证据”等绝对化说法。删除对ISO修订条款和达成合规的确定性承诺；新版不否认相关标准的价值，但不把未核对条款写成项目已成立的法律依据。

不再承诺小规模学生实验能证明“没有偏差”，也不从人脸推断种族等属性。仍评估可控制的光照、噪声等条件，并明确样本覆盖限制。

不再要求所有模型输出“原始概率”，改为保留工具实际提供的分数及其含义；分数不能被解释为作弊概率。原始观察、派生标记和人工意见分别保留版本记录。

不再将生产级不可变存储、多平台全面支持、外部mock服务和客户端完整API合同作为原型前置条件。仍要求审计历史、受限访问、版本记录、保留与删除机制，以及实际测试环境说明。

## 8 提交前由团队补齐的事实

1. 将 A、B、C、D 对应到真实姓名、学号、兴趣与技能，并确认谁参加12月考试。
2. 确认每人的可用工时及考后恢复时间；需要时调整相对周到日历的映射。
3. 填入学校真实的proposal、答辩、中期、海报和最终报告截止日期。
4. 与Petteri约定两周一次评审的具体时间，不把拟议时间写成已经获得的承诺。
5. 确认学校要求的封面字段、正式免责声明和成本计价规则；如有必须保留的模板，用真实规定替换当前通用字段。

以上是行政事实的补齐，不影响当前目标、流程和需求之间的对应关系。技术方案是否可行仍需执行E1至E6，不能仅靠修改proposal证明。
