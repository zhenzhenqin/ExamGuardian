## Moodle 联调

2026-11-18 在 WSL Moodle 4.5.15+、PHP 8.3、MariaDB 10.11 与 Django 5.2 下，使用单独的普通浏览器测试测验以及两个临时测试账号。两人各提交一次并各收件 3 段。测试员 A 翻页后仍使用同一会话。用 B 的网页登录状态登记 A 的作答时返回 HTTP 403。A 再次作答并拒绝录制，仍能提交。Moodle 将三次作答都记为 `finished`。手动运行 Moodle 提交事件产生的临时任务后，Django 收到前两次作答的结束信息并归档为「部分素材缺失」。拒绝的会话保留选择记录，媒体段数为 0。录制来源是测试脚本生成的轨道。

既有 SEB 测验在本机 Chromium 仍显示 SEB 启动控件，没有开放普通浏览器的答题入口。Moodle、SEB Server 的本机入口均返回 HTTP 200。

## 分析组件冒烟测试

MediaPipe 与 OpenCV Haar 均成功分析一场已归档的 Moodle 合成录制作答，两个任务各生成关联到证据的复核标记，总优先级均为 2。合成语音经本地编码进入 VAD，共得到 3 段语音区间、11.280 秒活动时长。对照用的合成连续纯音在开头产生约 80 毫秒活动，短于当前默认 3 秒阈值。实际论文指标以团队标注素材为准。[分析工具和评估命令](README.md#复现检查) · [OpenCV 模型来源](https://github.com/opencv/opencv/blob/4.13.0/data/haarcascades/haarcascade_frontalface_default.xml)

## 实机和论文验收

1. Windows SEB 用受控测试账号打开配置过的 Moodle Quiz。明确同意采集，用摄像头、麦克风至少录两段，进行一次翻页并交卷。
2. 在证据页核对真实 Moodle 作答编号、双轨、缺口及回跳。由分配到该会话的复核员保存意见。拒绝采集的另一作答仍能提交。
3. 独立记录 SEB Server 监控列表和实际学生计数。使用学校测试配置，不调整无关的测验配置。
4. 组员用同意的有脸、无人脸、多人脸、说话、静音资料完成受控实验。人工标注两轮后按留出集报告检测精确率、召回率和误报。脚本冒烟测试仅验证分析链路和工具能运行。

本报告记录本机原型的工程验收结果。多机 HTTPS、SEB 物理设备长录、SEB Server 教师监控计数和团队留出集需要实机或素材验收。
